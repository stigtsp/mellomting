# Fix plan for `docs/FIX_REVIEW_2026-08-22.md`

- **Base**: `11debd2` (HEAD at the time of writing).
- **Input**: `docs/FIX_REVIEW_2026-08-22.md` (three-pass review of the `b4beec4..11debd2`
  remediation), plus the findings it re-raised from `docs/CODE_REVIEW_CLAUDE_2026-08-21.md`
  that the previous `docs/FIXES_PLAN.md` never tasked.
- **How to use this file**: work **top to bottom, one item at a time**. Every item has a
  **Change** (what and where) and a **Verify** (the command/probe that must pass before the
  box is checked). Do not start the next item while the current Verify is failing. The
  **Final gate** runs after every item and again at the end. Mark items `[x]` only when
  their Verify passes.
- **Ordering rationale**: release-blocking defects first (each is a "Ship?"=blocks row in
  the review), then accounting/quota correctness, then performance, then strictness,
  then hardening/CI, then cosmetic. `FIX-02` must run on a **Linux host with Landlock
  ABI ≥ 6**; schedule it when such a host is available.
- **Failure rule**: never weaken a security invariant (PLAN §4) to make a test pass; a
  failed Verify means the fix is incomplete, not that the test should change.

## Phase A — Release blockers

### [ ] FIX-01 — N1: the key CLI must preserve the users file mode and ownership

**Change** — `internal/auth/Update` (`store.go:256-317`). Inside the lock, `os.Stat` the
existing file before creating the temp file; apply to the temp file the existing file's
mode **clamped to `0o640`** (never wider than 0640) and its uid/gid; remove the
unconditional `tmp.Chmod(0o600)` at `store.go:300`. This restores PLAN §29.1 ("mode
0600/0640 as appropriate" and "Preserve ownership safely") and fixes the shipped
`User=mellomting` deployment where `sudo mt key create` otherwise leaves a `0600 root:root`
file the daemon cannot read.

**Verify**
- Unit test `TestUpdatePreservesModeAndOwnership`: `0640 root:root` input → temp still
  `0640` and same uid/gid; `0600` input → stays `0600`.
- Live: `chmod 0640 users.yaml && mt key create … && stat -c '%a %u:%g' users.yaml` shows
  `640` and the original owner/group; daemon SIGHUP reload still succeeds.
- `go test ./internal/auth -count=1`; then the Final gate.

### [ ] FIX-02 — N2 + X2: SIGHUP revocation must not silently no-op under `landlock.mode: required`, and the Landlock fix must be proven executed

Two findings, one Linux run (ABI ≥ 6). N2: the landlock rule is bound to the users-file
**inode** (`serve.go:269` `ReadFiles`), but `auth.Update` atomically renames, so every
`key create/revoke/disable` makes the path a new inode the sandbox denies; `reloadUsers`
(`serve.go:596`) then fails closed by keeping the previous store — revocation *appears* to
succeed at every layer the operator sees. X2: the ABI-6/TSYNC fix (`apply_linux.go`) has
never executed anywhere.

**Change**
- Behaviour (N2): make `reloadUsers` log at **ERROR** and name the sandbox as the likely
  cause when the reload fails under `landlock.mode: required`. Adopt the review's
  recommended scoped fix — do **not** grant the rule on the parent directory (the shipped
  unit keeps `auth.pepper` and the TLS key beside the users file, so a directory grant
  would hand the sandbox the read it exists to deny). Either (a) place the users file alone
  in a dedicated directory and grant that, or (b) document in `docs/PLAN.md` §30/§29 and
  the unit file that key rotation/revocation under `mode: required` requires a restart, and
  make the ERROR log the observable signal.
- Proof (X2): add a CI job on an ABI ≥ 6 kernel that **fails when the Landlock acceptance
  test skips** (`apply_linux_test.go:49` guards on `landlock.DefaultMinimumABI`); add an
  integration case that revokes a key, sends SIGHUP, and asserts the revoked key now 401s.

**Verify**
- On the Linux host: `go test ./... -run 'Landlock|Reload|Revoke'` under `mode: required`:
  `mt key revoke -id X` then `kill -HUP $MAINPID` then `curl` with X → **401**, and the log
  shows the ERROR line if it cannot reload.
- CI job: without an ABI ≥ 6 kernel the job fails rather than silently skipping.
- Final gate on both hosts.

### [ ] FIX-03 — N3: `"stream": true` on `/v1/embeddings` must not bypass token accounting

**Change** — `internal/backend/backend.go:536`. Decide response liveness from the response's
`Content-Type` (`text/event-stream`) rather than from the client's `req.Stream` boolean, so
a plain `application/json` 200 is never fed to the SSE pump. Additionally reject
`stream: true` on non-generative endpoints (`/v1/embeddings`) with a 4xx, since OpenAI does
not stream embeddings and this is the only endpoint class where an SSE-misrouted 200 charges
zero tokens (`prepareOutbound` returns `reservation = 0` when there is no output cap).

**Verify**
- Unit test `TestEmbeddingsStreamDoesNotBypassAccounting`: same backend response
  (`"total_tokens": 1000`) with `stream=false` charges 1000; with `stream=true` the request
  is rejected (400) or, if allowed, still charges 1000 and returns `application/json`, never
  `text/event-stream`.
- Live probe through the real proxy against the mock backend, both `stream` values.
- `go test ./internal/backend ./internal/proxy ./internal/httpapi -count=1`; Final gate.

### [x] FIX-04 — N10: with `accounting.enabled: false` and quotas active, streams must not charge the whole output cap

**Change** — two parts:
1. `internal/proxy/proxy.go:105` — drive `ensureUsage` from "a quota is configured" rather
   than `cfg.Accounting.Enabled` (or expose the settings in accounting-disabled mode).
2. `internal/config/validate.go:437-444` — allow `ensure_stream_usage` and
   `unknown_usage_reservation` when `accounting.enabled` is false **but a per-key token
   quota is in use** (they govern quota, not the JSONL). Keep rejecting them when no quota
   exists.

**Verify**
- `config check` accepts `accounting:{enabled: false, ensure_stream_usage: true,
  unknown_usage_reservation: 500}` alongside a `tokens_per_hour` limit; and still rejects
  it when no quota is configured.
- Live probe (the review's scenario): `policy.max_output_tokens: 32768` and
  `tokens_per_hour: 100000`; tiny streaming completions must admit **well more than 3**
  before a 429 (i.e. real usage is settled, not the full 32768 reservation per stream).
- `go test ./internal/config ./internal/proxy ./internal/httpapi -count=1`; Final gate.

### [x] FIX-05 — M19: a draining process must not unlink its replacement's Unix socket

**Change** — `cmd/mellomting/serve.go:100-105`. Remove the deferred
`os.Remove(d.listenAddr())` for Unix listeners. Go already unlinks the socket when
`Shutdown` closes the listener at the *start* of the grace period (T-L11's liveness check
at `serve.go:396` stays). The deferred unlink fires up to `grace_period` later against
whatever now owns the path, killing a start-before-stop / blue-green replacement.

**Verify**
- Unit test `TestDrainingDoesNotUnlinkReplacementSocket`: A drains with a stalled in-flight
  request, B starts on the same path, wait past A's grace, assert **B is still reachable**
  and the socket file still exists.
- Live: reproduce the review's sequence with `grace_period: 25s`.
- `go test ./cmd/mellomting -count=1`; Final gate.

### [x] FIX-06 — Part 3a: a world-readable TLS **certificate** must be accepted (strict check stays on the key)

**Change** — `internal/tlsconfig/tls.go:23-31`. `Files` currently routes both cert and key
through `securefile.Read` (rejects `mode & 0o007 != 0`). Read the **certificate** with a
mode-check-free reader (keep `O_NOFOLLOW` and the regular-file check); keep the strict
`securefile.Read` for the **key** only. Certs are public data and are `0644` in mainstream
issuance (certbot `fullchain.pem`); PLAN §26 scopes `0640` to users file + pepper and §100
names only "strict file-permission checks" — neither names the cert.

**Verify**
- `chmod 0644 cert.pem && mt serve --config …` starts and serves TLS; `chmod 0644 key.pem`
  is still refused at startup.
- Update `tls_test.go` (currently pins the cert being refused at `tls_test.go:166-172`);
  keep a pin that the key stays strict.
- `go test ./internal/tlsconfig -count=1`; Final gate.

## Phase B — Accounting / quota correctness

### [x] FIX-07 — N4: `satAdd` and `usage report` must not produce `MaxInt64` for negative values

**Change** — `internal/accounting/quota.go:43` `satAdd`: reject or clamp negative addends
(before the `a > math.MaxInt64-b` guard, which itself overflows for `b < 0`). And
`internal/accounting/report.go:29-57` `ReportFile`: clamp record fields on read (reuse the
X11 `clampUsage` bounds) before feeding `satAdd`. This is reachable on any deployment whose
JSONL was written by a pre-fix binary or has one corrupt line.

**Verify**
- Unit tests `TestSatAddNegative` (`satAdd(0,-1) == 0` or error, never MaxInt64;
  `satAdd(100,-5) == 95`) and `TestReportFileClampsNegative`.
- Live CLI: the review's two-line log with `"output_tokens":-1` reports the correct total
  (49 in its example), never `9223372036854775807`.
- `go test ./internal/accounting -count=1`; Final gate.

### [x] FIX-08 — Part 2: `isUsageOnlyChunk` must not swallow `"usage": null` frames

**Change** — `internal/proxy/proxy.go:1157-1167`. `json.RawMessage` captures literal `null`
as 4 bytes, so `len(chunk.Usage) > 0` is true for `"usage":null`; an empty-choices frame
carrying `"usage":null` plus provider metadata is dropped instead of re-emitted verbatim
(PLAN §24). Add the review's fix: treat `bytes.Equal(chunk.Usage, []byte("null"))` as *not*
a usage-only chunk so the frame is relayed.

**Verify**
- Unit test `TestUsageNullFrameReEmitted`: a chunk `{"choices":[],"usage":null,...}` passes
  through to the client; only a real injected usage chunk (`"usage":{...}`, no choices) is
  swallowed when the proxy injected it.
- `go test ./internal/proxy -count=1`; Final gate.

### [x] FIX-09 — Part 2: `injectedUsage` must only be set when the key was actually injected

**Change** — `internal/proxy/proxy.go:1076-1080` with `clientRequestedUsage`/`injectStreamUsage`
(`:1121`, `:1145`). `injectStreamUsage` writes the key only when absent, so a client's
explicit `include_usage:false` is preserved upstream while `prepareOutbound` still reports
`injectedUsage = true`; the pump then swallows usage-only chunks it did not inject (reaching
FIX-08 through a second door). Track whether the key was **absent** before injecting and set
`injectedUsage` only in that case.

**Verify**
- Unit test `TestInjectedUsageOnlyWhenAbsent`: client sends `include_usage:false` →
  `injectedUsage == false`, upstream body keeps `false`, and a real usage-only chunk from
  the backend is relayed (not swallowed); client omits `stream_options` → `injectedUsage
  == true` and the injected usage-only chunk is swallowed.
- `go test ./internal/proxy -count=1`; Final gate.

### [x] FIX-10 — N6: the per-key concurrency 429 must carry `Retry-After`

**Change** — `internal/httpapi/server.go:269` calls `writeRateLimit(w, 0)`, and
`internal/httpapi/errors.go:32-41` emits the header only when `retryAfter > 0`. T-Q12's
criterion was "**all** 429 responses carry `Retry-After`". There is no computable wait for a
concurrency slot, so use the same conservative default the proxy quota path uses
(`defaultRetryAfter`, as at `proxy.go:356`), or amend the criterion in docs explicitly.
Prefer the header.

**Verify**
- Unit test asserting the concurrency 429 response has `Retry-After` (e.g. the value 1).
- Live: two concurrent requests on a `concurrent_requests: 1` key → the 429 carries
  `Retry-After`.
- `go test ./internal/httpapi -count=1`; Final gate.

### [x] FIX-11 — N7: the accounting log must be reopenable (and ship a logrotate policy)

**Change** — `internal/accounting.Writer` opens the JSONL once in `NewWriter` and holds the
fd forever; rename-based `logrotate` leaves the daemon appending to `usage.jsonl.1` and
`mt usage` reads an empty current file. Add a reopen path (e.g. on SIGHUP, matching the
users-file reload) **or** ship a `copytruncate` logrotate policy in `deploy/` and document
it. Note the N2 interaction: under `landlock.mode: required` a reopen of a new inode is
denied, so the doc must state that accounting reopen (like key reload) requires a restart in
that mode.

**Verify**
- If reopen added: unit test `TestWriterReopenWritesToNewFile`; live: rename the JSONL,
  SIGHUP, verify new rows land in the new file and `usage report` sees them.
- If copytruncate: `deploy/` contains a logrotate snippet and `COMPATIBILITY.md`/PLAN notes
  the mode-required restriction.
- `go test ./internal/accounting -count=1`; Final gate.

### [x] FIX-12 — Part 2: a live stream needs a cumulative byte bound

**Change** — `server.max_response_bytes` currently bounds only the buffered path
(`internal/backend/backend.go:106-108` documents this). Add a cumulative cap on the SSE
pump's emitted bytes (a stream byte budget in `internal/proxy`), in addition to
`stream_idle_timeout`, so a backend emitting small events forever cannot stream unbounded
data. On breach: terminate the stream with `backend_stream_error` (status already committed).

**Verify**
- Unit test `TestStreamCumulativeBound`: a backend emitting small events indefinitely is
  cut off after the cap with `backend_stream_error`; a normal stream under the cap is
  unaffected.
- Live: a long mock stream terminates at the cap.
- `go test ./internal/proxy ./internal/backend -count=1`; Final gate.
